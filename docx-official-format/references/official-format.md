# 文件印制格式基本要求

本规则依据用户提供的 `公文格式.doc` 整理，作为本项目默认 Word 排版依据。GB/T 15834-2011 标点符号规则仅作为辅助校对依据。

## 页面

- 统一使用 A4 纸。
- 页边距：上 `3.5cm`，下 `2.9cm`，左 `2.55cm`，右 `2.55cm`。
- 页眉距边界 `1.5cm`，页脚距边界 `2.2cm`。
- 段落使用固定值 `30 磅`。可视情使用 `28 磅`、`28.95 磅`、`29.7 磅`。
- 当正文中的一级标题排在页面最后一行时，可本着页面美观原则，对该页的行距、字间距作适当调整。
- **落款被挤到第二页（落款孤页）时，优先调行距，不要调字间距。** `w:spacing`（字间距）不改变断行数，调 -4 / -6 / -8 / -10 twips 都无效。有效组合：本页行距 30 磅 → 29.5 磅，落款署名段前 8 磅、日期行距 28 磅。
- **版式问题必须用实测坐标复核，不能凭公式自信。** 转PDF 后用 PyMuPDF 量每个文本块的 `x1`，算 `(版心右边界 − x1) / 字号pt = 右空字符数`，同组段落该值应一致。A4 宽595.304pt，版心右边界 = `595.304 − 右边距pt`。

## 字体与字号

- 标题：二号字，`方正小标宋_GBK`，加粗。
- 副标题：三号字，`方正楷体_GBK`。
- 正文：三号字，`方正仿宋_GBK`。
- 一级标题：三号字，`方正黑体_GBK`，序号形式为 `一、`。
- 二级标题：三号字，`方正楷体_GBK`，序号形式为 `（一）`。
- 三级标题：三号字，`方正仿宋_GBK`，加粗，序号形式为 `1.`。
- 四级标题：三号字，`方正仿宋_GBK`，序号形式为 `（1）`。
- 正文中结构层次的序数依次可用 `一、`、`（一）`、`1.`、`（1）` 标注，层次序数可以越级使用。

## 段落

- 正文各级标题均首行空两格，一般独立成行。
- 正文自然段首行空两格。
- 主送机关位于标题之后，左对齐，末尾使用全角冒号。

## 附件

- 附件说明用三号 `方正仿宋_GBK`。
- 附件说明位于正文之后、发文机关署名之前，与正文间隔一行。
- `附件` 前空 2 个字符，后接附件名称；附件名称后不加标点符号。
- 多个附件使用阿拉伯数字序号，例如 `1、2……`，分段序列，序号对齐，文字折行时首字对齐。

## 落款与日期

- 成文日期右空四字。
- 成文日期用阿拉伯数字将年、月、日标全，年份应标全称，月、日不编虚位，例如 `2026年8月5日`，不要写成 `2026年08月05日`。
- 单位名称位于正文之后；如有附件说明，则位于附件说明之后；下两行，居成文日期中。
- **长署名不要按「居成文日期中」处理，改为署名与日期统一右空四字、右边缘对齐。** 署名比日期宽时（如署名 15.00 字、日期 6.50 字），居中算出来署名会探出版心右边界。实务做法是两行都设 `right_indent = 四字`（64pt），右边缘齐平，既不越界又整齐。短署名（与日期宽度接近）才用居中。
- **右缩进方向判据**：署名比日期**宽**时，中心对齐所需的右缩进应当**更小**（`署名右空 = 4 − (署名宽 − 日期宽) ÷ 2`），写成加号会把署名往左推，出现「署名缩进比日期还多」的错位。
- 工具只有在最后一段是日期，且倒数第二段是真正的落款单位或姓名时，才将这两段作为落款日期处理；否则末尾段落仍按正文格式排版。
- 联系人、联系电话格式：`（联系人：……；联系电话：……）`。

## 页码

- 页码用宋体四号。
- 页码位置用外侧设置，首页不标页码。
- 页码样式为左右各一条四号字横线，例如 `— 2 —`。
- Word 操作路径参考：文件 -> 页面设置 -> 版式：页眉 `1.5cm`、页脚 `2.2cm`；插入 -> 页码，对齐方式为外侧；格式使用 `— 1 —`；选中页码后设置字体宋体、字号四号。

### 两个必须写对的地方（写错则「首页不编码」失效）

**1. 首页页脚要删 run，不能只清文本。**
把 `run.text` 置空后，run 内部的 `w:fldChar` / `w:instrText` 仍然存在，
域照样生效，**首页依然显示「— 1 —」**。必须整段删 run：

```python
for run in list(paragraph.runs):
    run._element.getparent().remove(run._element)
```

**2. 页码域必须拆成独立 run。**
`begin` / `instrText` / `separate` / 缓存结果 / `end` 塞进**同一个 run**
是非法结构。Word 会容错渲染，但严格实现会解析异常，导致 `titlePg`
行为失效。正确写法是每个标记一个 run：

```
<w:r><w:fldChar w:fldCharType="begin"/></w:r>
<w:r><w:instrText xml:space="preserve"> PAGE </w:instrText></w:r>
<w:r><w:fldChar w:fldCharType="separate"/></w:r>
<w:r><w:t>1</w:t></w:r>
<w:r><w:fldChar w:fldCharType="end"/></w:r>
```

**校验陷阱**：`paragraph.text == ""` 查不出域残留——空 run 的 text 也是空。
必须断言 XML 里不含 `w:fldChar` / `w:instrText` / `PAGE`。

### 关于「首页不编码」后的编号

首页不显示页码，但**编号仍按物理页序**——第 2 页显示「— 2 —」是正确行为。
设 `w:pgNumType w:start="1"` 无法让第 2 页变成「— 1 —」，
因为 titlePg 只隐藏首页、不重排计数。GB/T 9704 的要求是「首页不标页码」，
不是「首页不计入页数」。

## 标点

- 中文正文优先使用中文全角点号：`，`、`。`、`；`、`：`、`？`、`！`、`、`。
- **正式材料不得使用半角标点。** 半角 `"` `'` `,` `;` `:` `(` `)` 一律改为全角，这是最常见的格式硬伤。
- **双引号必须全角且成对**：用 `“` `”`，不用 `"` `"`。嵌套时外双内单，如 `“……‘渝见’……”`。
- 允许保留半角的例外：代码块与命令、英文缩写（App、IoT）、小数点（3.5）、千分位（1,200）、百分号（%）、负号（-3.2%）、尺寸记号（6'6"、6′6″）。
- 标题末尾通常不用句号、逗号、顿号、分号、冒号。
- 附件说明使用 `附件：`，附件名称后不加标点符号。
- 公文发文字号年份使用六角括号 `〔〕`。
- 省略号统一为 `……`；省略号不宜与 `等`、`等等` 同时使用。
- 成对标号如引号、括号、书名号应前后配套；无法安全自动修改时，工具会标红并写入 Word 批注。

### 引号速查

| 半角（错） | 全角（对） |
|---|---|
| `"` `"` | `“` `”` |
| `'` `'` | `‘` `’` |
| `,` | `，` |
| `;` | `；` |
| `:` | `：` |
| `(` `)` | `（` `）` |
| `?` `!` | `？` `！` |

嵌套层级：外双内单（`“……‘内层’……”`），不得外双内双。

## 中英混排：西文与数字走 Times New Roman

公文中凡出现**英文、阿拉伯数字、百分号、小数点、千分位**，一律用 **Times New Roman**；
中文汉字与全角标点（含中文引号）用方正字体。**双引号仍用中文全角**，这两条是并行的。

| 内容 | 字体 |
|---|---|
| 中文汉字、全角标点、中文引号 | 方正_*_GBK（按层级定） |
| 英文单词、缩写 | **Times New Roman** |
| 阿拉伯数字 `2026` `500` `35` | **Times New Roman** |
| 百分号 `11.7%`、小数点、千分位 `1,200` | **Times New Roman** |

**实现要点**：`run.font.name` **只写 `w:rFonts` 的 `w:ascii` 槽位**，
把中文字体名设进去会导致西文也用中文字体渲染。OOXML 的 `rFonts` 是**四槽位**，
必须按槽位分工手工设置，并补 `w:lang` 防 Word 替换：

```python
rF = run._element.get_or_add_rPr().get_or_add_rFonts()
rF.set(qn('w:ascii'),    'Times New Roman')   # 拉丁字母、数字、%、小数点
rF.set(qn('w:hAnsi'),   'Times New Roman')
rF.set(qn('w:cs'),      'Times New Roman')
rF.set(qn('w:eastAsia'), '方正仿宋_GBK')       # 只管汉字与全角标点
lang.set(qn('w:val'), 'en-US')
lang.set(qn('w:eastAsia'), 'zh-CN')
```

## 全角引号必须独占 run 并声明 hint

**这是「字符对了但看着像直引号」的坑。** 正文写的确实是 `“”`（U+201C/U+201D），
打开却显示成直引号形状——根因不在字符，而在**字形选取**。

**两个必要条件**（缺一即退回西文字形）：

1. **全角引号独占一个 run**，不与汉字正文混在同一个 run
2. **该 run 声明 `w:hint="eastAsia"`**：

```python
rF.set(qn('w:hint'), 'eastAsia')   # 中文 run
rF.set(qn('w:hint'), 'default')    # 纯西文 run
```

只设 `eastAsia` 槽位是不够的——Word 对全角标点的取字判断依赖 `hint`，
缺省时退回 `ascii` 槽位，于是 `“”` 被 Times New Roman 渲染，
字形细长、位置偏高，**看起来就是直引号**。

切分时把全角标点一并单独切出来：

```python
FULLWIDTH_PUNCT = '“”‘’（）〔〕【】《》〈〉、。，；：？！…—～·％‰℃'
```

**验证方法**：读回 docx 确认引号是独立 run 且 `hint == 'eastAsia'`；
再转 PDF **放大**目视——中文字体的弯引号比 Times New Roman 的更饱满、位置居中。
不放大看不出来，别只看字符统计就下结论。

**校验陷阱**：`run.font.name` 读回来拿到的是 **ascii 槽位**（恒为 Times New Roman）。
校验中文字体必须读 `rF.get(qn('w:eastAsia'))`，不能拿 `run.font.name` 比对中文名。

## 字体名称规范

**必须用「方正」系列带 `_GBK` 后缀的完整字体名**，简称（`黑体`、`楷体`、`仿宋_GB2312`）不规范。

| 用途 | 字体名 | PostScript |
|---|---|---|
| 标题 | 方正小标宋_GBK | FZXiaoBiaoSong-B05 |
| 正文 / 落款 / 主送机关 | 方正仿宋_GBK | FZFangSong-Z02 |
| 一级标题「一、」 | 方正黑体_GBK | FZHei-B01 |
| 二级标题「（一）」 | 方正楷体_GBK | FZKai-Z03 |
| 页码 | 宋体 | — |

**注意区分**：`方正仿宋_GBK`(FZFangSong-Z02) 与 `方正仿宋简体`(Z02S) 是两套字体，
公文用 **GBK** 那个，别混。

## 其他

- 如有附注，居左空二字加圆括号编排在成文日期下一行。
- 表格中的字体、字号可参照上述标准，字号可根据实际情况缩小。
